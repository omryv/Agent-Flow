The Problem

Debugging LLM agent failures is opaque and time-consuming

When an LLM agent produces the wrong answer, developers need to understand which step failed, why it failed, and what would have happened if a different decision was made.

Existing trace viewers from LangSmith, LangFuse, and W&B Weave show the original execution, but they don't let you visualize counterfactual scenarios embedded in the trace itself.

  • No way to compare "what happened" vs "what could have happened" side-by-side
  • No visual diff of node-level changes between scenarios
  • No clear metric deltas (time, tokens) when switching between runs
  • No isolation from backend dependencies — traces are locked to vendor platforms

The Solution

A focused, browser-native counterfactual trace inspector

AgentFlow is a single-page application that runs entirely in your browser. No backend. No runtime dependencies. Import a trace file, visualize the execution graph, and explore embedded counterfactual scenarios.

Core Logic

DAG Layout Algorithm

▼

Kahn's topological sort via BFS

  1. Compute in-degrees for all nodes
  2. Collect all zero-in-degree nodes into layer 0
  3. For each node in the current layer, decrement in-degrees of its neighbors
  4. Nodes that reach in-degree 0 enter the next layer
  5. Repeat until queue is empty
  6. Any unvisited nodes (cycles) are placed in single-node layers

Position formula:

  • x = 40 + layerIndex × 280
  • y = max(40, (600 − totalLayerHeight) / 2) + nodeIndexInLayer × 170

Counterfactual Materialization

▼

Read-time computation — no mutation of stored runs

  1. Deep-clone the base run
  2. Apply nodeOverrides map (merge partial node fields)
  3. If full nodes array is provided, replace entirely
  4. If full edges array is provided, replace entirely
  5. Detect removed nodes (present in base, absent in CF) and add to override set
  6. Merge metrics — per-field, with fallback to base values
  7. Replace finalAnswer if provided

Overridden nodes are highlighted with a blue glow. Removed nodes are visually marked. Metrics bar shows +N ms / −N tokens deltas.

Schema Validation

▼

Multi-layer validation on import

  • Root object must have id, name, nodes, edges
  • All IDs must match SAFE_ID_RE (alphanumeric, dash, underscore only)
  • Node names ≤ 200 chars, content ≤ 10,000 chars
  • Max 500 nodes, max 2,000 edges
  • Referential integrity: all edge from / to must reference existing node IDs
  • Counterfactual IDs and nodeOverride keys must be valid node IDs

Invalid runs are rejected with plain-English error messages. Existing session state is never touched.

Role & Status Inference

▼

Keyword-based classification for imported traces

inferRole(type, name): Maps trace step types to AgentFlow roles (input, retrieve, plan, tool, synthesize, validate, output). Checks both the type field and the name field for keywords like "retrieval", "generation", "tool", "chain", etc. Defaults to plan if no match.

inferStatus(error): Maps error presence to failed vs success.

  • Interactive counterfactual authoring (CFs come from import file)
  • Drag-to-reposition nodes (algorithm-determined layout)
  • Live streaming / real-time traces (static imports only)
  • Node search or filtering (out of scope for v1)
  • Command palette (future enhancement)
  • Sample data on first load (empty state prompts import)
  • Backend API or database (browser-only)

Why This Scope is Disciplined

AgentFlow is a read-only inspector, not an authoring tool. This constraint keeps the codebase small, security surface minimal, and UI focused. No backend means no auth, no server costs, and no vendor lock-in. Counterfactuals are authored externally (by your trace generation pipeline) and embedded in the import file — AgentFlow just visualizes them.

The result: a tool you can trust with sensitive traces, host on any static server, and run offline.
